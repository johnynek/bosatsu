## Summary

Extend the existing external-declaration parser and statement renderer so `external type` is the canonical spelling while `external struct` remains a source-compatible alias. Both forms will continue through the existing `Statement.ExternalStruct` node and constructorless lowering, and the bounded repository-owned source, fixture, and documentation inventory will migrate to the canonical spelling without backend or runtime changes.

Plan trajectory: initial steps 3; review revisions 0; review-origin steps 0.

## Current State

On `main`, the `external` branch in `Statement.parser1` accepts only `structKey` for opaque type declarations, constructs `Statement.ExternalStruct`, and its `Document[Statement]` case emits `external struct`. `SourceConverter` already lowers this node to a constructorless `rankn.DefinedType` with invariant defaults for unannotated parameters, while `Package` uses the same node for synthetic function types; no downstream consumer records the source spelling. `Generators.genExternalStruct` participates in the general statement round-trip property, but there is no explicit new/legacy spelling equivalence or soft-keyword ambiguity coverage. Repository-owned predef/workspace declarations, embedded programs in nine semantic test suites, and older documentation still use the historical spelling. The tree-sitter grammar is line-oriented and already accepts the new token sequence, so it needs no change.

## Problem

`external struct` gives an opaque externally owned type a product-type name even though Bosatsu knows no constructors, fields, or runtime representation for it. Now that transparent aliases use `type Foo = Bar`, the representation-neutral declaration should be `external type Foo`. The canonical syntax and repository examples must change without breaking existing source that uses `external struct`, accidentally routing external values named `type` into the type-declaration branch, or changing opacity, kind inference, exports, serialization, evaluation, or code generation.
